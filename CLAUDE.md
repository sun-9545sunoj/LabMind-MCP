# CLAUDE.md

This file provides guidance to Claude Code (claude.ai/code) when working with code in this repository.

## What this is

LabMind-MCP: a Python MCP server (FastMCP, stdio transport) that exposes a mock Laboratory Information System plus ML models (Isolation Forest anomaly detection, XGBoost sepsis risk with SHAP, linear-regression trend analysis) to AI agents as 6 tools, 3 `lis://` resources, and 2 prompts. All patient data is synthetic.

## Commands

```bash
python -m venv .venv && source .venv/bin/activate
pip install -e ".[dev]"

python -m labmind.data.seed_database   # (re)create labmind/data/labmind.db — deletes the existing DB first
python -m labmind.ml.train_models      # train + save both models to labmind/ml/models/*.joblib (needs the DB)
python -m labmind.server               # run the MCP server over stdio (also: `labmind-mcp`)

ruff check .                           # lint (rules E,F,I,N,W,UP; line length 88; py311 target)
pytest                                 # full suite (~5s)
pytest tests/test_server.py::test_analyze_lab_trend   # single test
```

Tests never touch the real DB or `.joblib` files: `tests/conftest.py` seeds a temp DB and trains both models in memory (session-scoped), and the `server` fixture monkeypatches the server's lazy singletons to use them. Tools catch their own exceptions, so server tests assert the output contains no `❌` rather than expecting a raise.

Setup order matters: seed → train → serve. The DB and `.joblib` files are gitignored and regenerated by these scripts.

## Architecture

- `labmind/config.py` is the single source of truth for paths (DB and model files live *inside* the package dir), hyperparameters (overridable via `LABMIND_*` env vars), feature lists (`ANOMALY_FEATURES`, `SEPSIS_*_FEATURES`), sepsis risk thresholds, and the `LOINC_CODES` table.
- `labmind/server.py` holds every tool, resource, and prompt. DB and models are lazy-loaded module-level singletons (`_get_db()`, `_get_anomaly_detector()`, …). A missing model file makes the getter return `None`, and the tool returns an error string telling the user to run training — the server still starts. Every tool catches exceptions and returns a markdown string (emoji status markers, tables) rather than raising.
- `labmind/db/database.py`: `LabDatabase` wraps a single sqlite3 connection and returns typed dataclasses (`Patient`, `LabResult`, `ReferenceRange`). `is_abnormal`/`status` are computed properties; `is_critical` is stored in the DB (set by the seeder).
- `labmind/ml/`: each model class has `train()`, `save_model()`/`load_model()` (joblib), and an inference method returning a result dataclass. The sepsis predictor is trained on synthetic data from `generate_sepsis_training_data()`, not on the DB; the anomaly detector is trained on every historical lab panel in the DB (`build_anomaly_training_frame`). Training only on latest panels over-weights deteriorating patients' end states and made the model treat severe panels as normal. `SepsisRiskPredictor.predict()` fills missing features with hard-coded normal defaults.
- `labmind/data/seed_database.py` defines the schema (`patients`, `lab_results`, `reference_ranges`) and reference ranges, and generates 60 patients (`P001`…`P060`); the first ~10% follow sepsis trajectories and the next ~8% AKI trajectories.

### Non-obvious coupling

- ML feature keys come from `test_name.lower()` on DB rows (e.g. `"WBC"` → `wbc`, `"BUN"` → `bun`). Renaming a test in the seeder's reference ranges silently drops that feature from the models; keep test names consistent with the feature lists in `config.py`.
- Seed data is anchored to the time of seeding: each patient's draws are strictly increasing, 1–5 days apart, ending the day before (`seed_database(reference_time=...)` pins it). `get_lab_trend` filters relative to `datetime.now()`, so a DB seeded more than ~180 days ago returns empty trends; reseed and retrain.
- `predict_sepsis_risk` vitals are optional. Missing vitals fall back to `DEFAULT_VITALS` and are marked as assumed in the output.
- `analyze_lab_trend` takes a LOINC code (e.g. `2160-0` for creatinine), not a test name. The other tools work on test names.
- `mcp` 2.x renamed `mcp.server.fastmcp.FastMCP` to `mcp.server.mcpserver.MCPServer`; `server.py` imports whichever exists, and `pyproject.toml` allows `>=1.2.0,<3`. Both 1.30 and 2.0 have been verified against the test suite.
- Retraining is required after reseeding for the anomaly detector to reflect the new data.
